README and how it works

This page is a viewer. It holds no medical content of its own: the three trees live in three JSON files next to it, and the page reads them when it opens.

What is in the package

FileWhat it does
TAUMD_Micro_Trees.htmlThe viewer: tabs, search, tree drawing, this README.
bacteria.jsonGram-positive, Gram-negative and poorly staining bacteria.
fungi.jsonDimorphic, opportunistic, cutaneous and subcutaneous fungi.
virology.jsonDNA and RNA viruses by envelope, genome and family.

Keep all four files together in one folder. The page looks for the JSON files by name, in its own folder.

How it works, step by step

  1. The page opens and reads its file list.At the top of its script is DATA_FILES: ["bacteria.json", "fungi.json", "virology.json"].
  2. It fetches each JSON file.Each file is requested from the same folder with fetch(). This works when the page is served over http or https, for example from your website or a local server.
  3. If the browser refuses, you pick the files.A page opened by double-click (address starts with file://) is not allowed to read its neighbours. The page then shows a file picker: select all three JSON files at once, or drop them on the window. They are read inside your browser and never uploaded. A copy is remembered in this browser so the next double-click opens straight away.
  4. Each file is checked.It must be valid JSON with a meta.id and a non-empty tree. A problem is reported by file name in the status table below, and one bad file never stops the others.
  5. Every valid file becomes a tab.The tab name, color and icon come from the file's meta block. Tabs are ordered by meta.order.
  6. The tree is drawn from the nested children.A node with children is a branch you can fold and unfold. A node without children is an entry: its name and badges, then its notes and detail cards.
  7. Search runs on all trees at once.Every word must match, in any order, in a node (name, badges, notes, details) or in the branches above it, so “naked rna” finds the naked RNA viruses. Matches are highlighted, matching branches open, and each tab shows its match count.

Three ways to open it

A. On your website (recommended)

Upload all four files to the same folder. Nothing else to do: the JSON files load automatically.

B. Local server

Open a terminal in the folder and run:

python3 -m http.server 8000
# Windows: py -m http.server 8000

Then open http://localhost:8000/TAUMD_Micro_Trees.html. This always reads the current JSON files.

C. Double-click the HTML file

Press Load files (top right), then select bacteria.json, fungi.json and virology.json together. In the folder window, Ctrl/Cmd + A selects them all.

Using the viewer

  • Tabs switch between trees. Arrow keys move between tabs.
  • Search filters every tree. Press / to jump to the box and Esc to clear it.
  • Expand all and Collapse all work on the tab you are looking at.
  • Hide details keeps only names and badges so you can test yourself. Click any entry to reveal its notes.
  • Print opens every branch first, so the whole tree lands on paper.

Editing the data

Open any JSON file in a text editor, change it, and reload the page. The structure is the same in all three files:

{
  "schema": "taumd-tree/1",
  "meta": {
    "id": "parasites",          // required, unique, no spaces
    "title": "Parasites",       // tab name
    "subtitle": "Protozoa and helminths",
    "icon": "tree",             // bacteria | fungus | virus | tree
    "accent": "#0f766e",        // tab and entry color
    "order": 4                  // tab position
  },
  "legend": [
    { "title": "Legend",
      "items": ["{buzzword|Yellow} marks a high-yield buzzword."] }
  ],
  "tree": [
    { "name": "Protozoa", "type": "category", "color": "#0f766e",
      "children": [
        { "name": "Giardia lamblia", "type": "species",
          "badges": ["Flagellated", { "text": "Waterborne", "tone": "blue" }],
          "notes": "Foul-smelling, **fatty** diarrhea in campers.",
          "details": [
            { "label": "Diagnosis", "text": "Stool microscopy: trophozoites and cysts." },
            { "label": "Treatment", "list": ["Metronidazole", "Tinidazole"], "wide": true }
          ] }
      ] }
  ]
}

The comments after // are only for this README. Real JSON does not allow comments, so leave them out of your files.

Node fields (everything in tree)

FieldNeededMeaning
nameyesText shown for the node.
childrennoList of nodes. With children it is a branch; without, an entry.
typenoChooses the icon and tint: root, category, branch, genome, envelope-status, family, species. Any other word works too. species names are set in italics.
badgesnoSmall tags. Plain text, or {"text": "…", "tone": "…"}. Tones: sens (green), res (red), purple, blue, amber, teal, gray. Plain text containing "sensitive" or "resistant" turns green or red by itself.
notesnoOne short paragraph. On an entry it sits in a box under the name; on a branch it is the caption under the name.
detailsnoCards under an entry. Each is {"label": "…", "text": "…"} or {"label": "…", "list": ["…"]}. Add "wide": true for a full-width card.
colornoBar color of a top-level node, as #rrggbb. Defaults to the tab's accent.
isExpandednofalse starts the node folded.
idnoFree label for your own use. Not displayed.

Text formatting inside any text field

**bold**, *italic* and {buzzword|high-yield phrase} (yellow highlight). Everything else is shown as plain text, so characters like < and & are safe.

Legend groups

Each group is {"title": "…", "tone": "blue", "items": […]}. An item is a plain string, {"swatch": "#hex", "text": "…"} for a color dot, or {"badge": "Label", "tone": "sens", "text": "…"} for a sample badge.

Adding a fourth tree

  1. Copy fungi.json to a new name, for example parasites.json.
  2. Change meta.id, meta.title and meta.accent, then replace the tree.
  3. Add the file name to DATA_FILES near the top of this page's script, or select it with Load files.
  4. Reload. A new tab appears by itself, and search covers it too.

If something looks wrong

You seeWhy and what to do
"Choose the data files" card on openThe page was opened from disk, so the browser blocked fetch(). Use Choose JSON files, or open it the way B or A above describes.
"Not valid JSON"A comma, quote or bracket is missing in that file. Paste the file into any JSON checker to find the line.
Edited JSON, nothing changedThe page is showing its saved copy (a note says so above the tree). Press Load files and select the edited files again, or use option B.
A tab is missingCheck the status table below: it names each file and the reason it was skipped.
A top bar is hard to readUse a darker color. Text on the bar switches between white and black automatically.
